# SockLock Variants

Внутрішня вебсторінка для motion-дизайнерів SockLock: вставляєш скрипт переможця — за ~30–40 секунд
отримуєш 20 варіантів хука, першої фрази й тексту на екрані під таймінг відео, з тегами, перевірками
і назвами за конвенцією UA. Будь-який варіант можна доправити в чаті.

**Навіщо.** Дизайнер: «Половину дня я переписую одне й те саме: беру скрипт переможця і вручну
придумую нові хуки, перші фрази, варіанти тексту на екрані». Через це команда робить ~240 модифікацій
на місяць, а для $800k spend треба ~500. Інструмент скорочує текстову частину модифікації з ~1,5 год
до ~10 хв перевірки: модифікація ≈1,7 год замість 3, ≈430 модифікацій тими самими 6 дизайнерами,
**+$67k EGP на місяць** (базовий сценарій). Розрахунок, build vs buy і пітч —
[у документі](https://claude.ai/artifact/BDwp6yfmSbLkZw4kj7aw8f).

## Запуск

Потрібні Python 3.12+ і [uv](https://docs.astral.sh/uv/).

```bash
uv sync
cp .env.example .env          # обрати бекенд, див. нижче
uv run uvicorn socklock_variants.web:create_app --factory --port 8000
# відкрити http://localhost:8000
```

На сторінці натисни «встав приклад» → «Згенерувати». Приклади скриптів лежать у `evals/scripts/`.

### Бекенд моделі (`.env`)

| `LLM_BACKEND` | Що використовує | Коли |
|---|---|---|
| `api` | Claude API, модель `claude-sonnet-5-5`, потрібен `ANTHROPIC_API_KEY` | прод: дизайнери працюють тільки з вебсторінкою |
| `cli` | локальний `claude -p` (Claude Code) на підписці | розробка, тести, evals — без витрат API-токенів |

Обидва бекенди просять у моделі відповідь строго за JSON-схемою (structured outputs), тож відповідь
завжди розбирається.

**Вартість у проді:** ≈$0,13 за сесію (генерація + 2 правки), ≈430 сесій → ≈$55/міс,
закладаємо до $100/міс. Інфраструктури понад внутрішній сервер немає: без бази, без логіну,
сесії в пам'яті.

## Формат скрипту

```
W12 · Washer thief
HOOK 0-2.5s | VO: "Lost another sock?" | ON-SCREEN: "Your washer eats socks"
PROBLEM 2.5-7s | VO: "Every wash, one goes missing..."
PRODUCT 7-15s | VO: "SockLock magnets keep pairs together"
CTA 15-20s | VO: "Get your first pack for $29"
```

Перший рядок — ID переможця (`W12`) і назва. Далі по рядку на сегмент: назва, таймінг, `VO` та/або
`ON-SCREEN`. Прямі й «криві» лапки, en-dash і `.txt`/`.csv` з файлу теж працюють. Якщо вставити
просто текст, інструмент його прийме, але таймінг перевірятиме за замовчуванням (хук 2,5 с).

## Як це працює

```
скрипт ─► parse_script ─► Claude (system prompt + JSON-схема) ─► перевірки кодом ─► 1 повтор для проблемних ─► неймінг ─► таблиця
                                                                                                         └─► чат з варіантом ─► v07b, v07c…
```

- **Що змінюється:** `HOOK` (голос перших секунд), `FIRSTLINE` (перша фраза після хука),
  `ONSCREEN` (текст на екрані). Модель може трохи підлаштувати одну сусідню фразу, щоб новий хук
  логічно переходив далі; це підсвічується жовтим у повному скрипті.
- **Кути:** біль, цікавість, гумор, демонстрація, соцдоказ, проти течії, цифра, питання.
- **Перевірки (`checks.py`, без LLM):** таймінг (голос ≈2,5 слова/с, текст на екрані ≤7 слів),
  ризикові обіцянки (guaranteed, 100%, forever, never lose, медичні, #1…), різноманітність (без
  однакового початку й майже-дублів), сусідня зміна лише поруч із вибраним елементом. Що не пройшло —
  перегенеровується один раз; що не пройшло вдруге — показується з червоним тегом, а не ховається.
- **Неймінг:** `W12_HOOK_pain_v07` — переможець, елемент, кут, номер; правки в чаті → `v07b`.
  За назвою з експорту Meta потім видно, з чого виросла модифікація і чому її взяли.
- **Сесії:** кожна генерація — окрема сесія за cookie, дизайнери не бачать і не ламають генерації
  одне одного.

```
socklock_variants/
  script.py       розбір скрипту
  prompts/system.md  системний промпт
  llm.py          ApiLLM (Claude API) / CliLLM (claude -p)
  generator.py    генерація, JSON-схеми, повтор, правки в чаті
  checks.py       детерміновані перевірки
  naming.py       конвенція назв
  sessions.py     сесії в пам'яті
  web.py          FastAPI
  static/         сторінка (без збірки)
evals/            9 вигаданих переможців + run.py
tests/            pytest, фейковий LLM, без мережі
```

## Тести й evals

```bash
uv run pytest                                  # 31 тест, без мережі
uv run python evals/run.py --count 20          # 9 скриптів × 20 варіантів через claude -p
```

Evals ганяють генератор на 9 вигаданих переможцях різного формату (голос, тільки текст, короткий
12-секундний ролик, UK, вільний текст без розмітки) і рахують метрики тими самими перевірками, що й
застосунок, плюс LLM-суддя ставить кожному варіанту 1–5: «про той самий продукт і біль»,
«конкретно, а не загально», «звучить природно вголос».

Останній прогін (9 × 20, `claude-sonnet-5-5`):

| Метрика | Результат | Ціль |
|---|---|---|
| Скриптів без помилок | 9/9, по 20/20 варіантів | 100% |
| Вкладаються в таймінг | 98% | ≥95% |
| Ризикових обіцянок | 0 | 0 |
| Різних кутів на 20 варіантів | 8 | ≥6 |
| Дублів початку | 0 | 0 |
| Суддя, середнє 1–5 | 3,76 (про продукт ≈4,0, природність ≈4,0, конкретність ≈3,3) | ≥4,0 |

Перший прогін знайшов справжній баг: 2 з 9 скриптів давали 0 варіантів, бо модель зрідка ламала
JSON. Виправлено переходом на structured outputs. Найслабше місце зараз — конкретність (≈3,3):
частина хуків загальна. Це перше, що покращувати промптом (див. «Наступна ітерація»).

## Як міряємо успіх

Пілот: 2 тижні на 2–3 дизайнерах, потім усі 6.

| Метрика | Зараз | Ціль | Коли |
|---|---|---|---|
| Хвилин на текстову частину модифікації | ≈90 | ≤10 | пілот, 2 тижні |
| Частка варіантів, які дизайнер бере без правок | — | ≥50% | пілот, 2 тижні |
| Годин на модифікацію | 3 | ≈1,7 | 1 місяць |
| Модифікацій на місяць | 240 | ≈430 | 1–2 місяці |
| Spend / EGP | $400k / $140k | ≈$690k / ≈$207k | 2–3 місяці |
| ROMI модифікацій | 140% | ≥125% | постійно |

Як рахуємо: час — коротким самозаміром дизайнерів до/після; частку «без правок» — порівнянням
скопійованого тексту з тим, що пішло в рекламу (CSV з назвами); обсяг і ROMI — з наявної звітності UA
за назвами `W.._..._v..`. Якщо ROMI модифікацій з інструмента падає нижче 125% — зупиняємо і
розбираємось, які кути не працюють.

## Наступна ітерація

1. **Конкретність хуків** — гнати evals у циклі й правити промпт, поки суддя не дасть ≥4 по
   конкретності; додати в промпт 5–10 найкращих хуків, які дизайнери взяли без правок.
2. **Бібліотека переможців** — зберігати скрипти, щоб не вставляти їх щоразу.
3. **Журнал вибору** — які варіанти дизайнер скопіював, які переписав: найкращі приклади для промпту.
4. **Далека перспектива, не факт:** з CSV-експортом Meta й достатнім обсягом даних (сотні модифікацій)
   підмішувати в генерацію, які кути реально перформлять.
5. Деплой на внутрішній сервер (Docker) з `LLM_BACKEND=api`.
